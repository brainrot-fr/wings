Defects found in the alirezarezvani material
Likely fabricated citations in senior-backend/forcing_questions.md. Examples are “Andrew Clay Shafer, The SLO Handbook (2019)”, “Aaron Patterson + Rails security advisories”, and “Reinertsen Principle Q5”. Given your preference for verified sources, drop the citations and keep only the questions.
Composition map points at skills that don’t exist in the clone, and the scripts (backend_decision_engine.py and others) weren’t sent.
Index advice in database-designer (“most selective column first”) contradicts oma’s “equality predicates first, then range or sort”. oma is correct.
SSRF blocklist by hostname regex in backend_security_practices.md is bypassable (decimal and IPv6 forms, DNS rebinding). Addy’s resolve-all-addresses approach is better.
resolved.startsWith(baseDir) path check accepts sibling prefixes such as /base-evil. Addy’s relative() check is correct.

Conflicts and proposed house rules
Conflict	House rule
Password hashing: bcrypt ≥12 (Addy, senior-backend) vs Argon2id (oma)	Argon2id by default, bcrypt accepted as legacy
Validation status: 400 (acceptance patterns, senior-backend) vs 422 (Addy)	400 for malformed, 422 for failed validation
Error envelope: three variants	Addy’s {error:{code,message,details}} plus requestId, no timestamp
Pagination: offset/page/cursor in three shapes	Cursor/keyset by default, offset only for small bounded lists, one envelope
Soft delete: “best practice” (schema-designer) vs “anti-pattern everywhere” (sql-assistant)	Only where retention or restore is a stated requirement, with a partial index
Money type: FLOAT, DECIMAL(19,4), or integer cents	Never float; NUMERIC or integer minor units
PK type: UUIDv4, UUIDv7, cuid, identity	A decision-record item, default UUIDv7 on PG18+, otherwise identity bigint
Layering: router→service→repo (oma) vs DDD hexagonal (ccheney)	Layered by default; DDD only when its trigger criteria apply
Coverage: 80% mandate, “auth 100%” (tdd-guide, senior-qa)	Already decided: value bar
JWT/session: HS256, RS256, sessions	Stack decision record chooses; access ≤15 min, revocation story required
oma backend.md rule 11 (fallback when API key is absent) vs Trail of Bits’ fail-open rule (“env.get(X, Y) runs, env[X] crashes”)	Never fall back for signing, session or encryption secrets. They fail at startup. A third-party key may use a labeled simulated mode, never silently in production.
Severity: critical to info (Cloudflare), CRITICAL to LOW (oma), HIGH/MEDIUM/LOW (Semgrep)	P0 to P3, with confidence as a separate field

Batch 3: security design
Cloudflare security-audit

It is the strongest source and also the heaviest.

Keep:

Three verdicts: confirmed, needs_validation and rejected. Only confirmed findings get severity.
Candidate gate. Every finding names the lower-trust principal, the crossed boundary, the affected resource and a concrete result. A missing best practice or a guessed deployment fact is not a finding.
Source-visibility rule. A control outside the repository is never assumed present or absent. It becomes needs_validation with the exact owner-observable fact.
Severity anchors and the high/medium discriminator. Does the result fully defeat a control, or only weaken it?
Stable root-cause fingerprint across states, and independent re-verification of every confirmed finding by a fresh context (labeled degraded fallback).
Companion attack-class files. The classes are web/auth, client-side, data isolation and lifecycle, cloud, supply chain, AI/LLM, protocols and messaging, resource exhaustion, and desktop and local IPC. Rewrite them as wings review lenses. They already follow a pattern: Core discipline, classes, Universal moves, Validation rules.
Coverage ledger idea. Surface × boundary × attack class maps onto BMAD’s surface closure.

Drop or simplify:

The OS sandbox, parent-side descriptor promotion, and per-agent scratch and artifact trees.
The Node validators and the JSON-Schema interpreter.
Canonical percent-encoded coverage IDs, budgets and run profiles.

Wings audits the app it just built and has no hostile target code, so full audit mode becomes optional. The default is a lens pass over FN/TB/PG IDs.

Addy security-and-hardening

It is the build-time spine: STRIDE per trust boundary, always/ask/never tiers, hardening patterns, and the destructive-path rule (allowlisted root, minimum depth, ownership evidence). Skip the npm install-script version matrix (npm 11.18/12.0.1 and others). It is a dated snapshot and will rot.

Semgrep
It is a rule corpus (28 categories with incorrect/correct snippets per language). The model already knows most of it, so add only gotchas.
The rule-file format (title, impact, impactDescription, tags, incorrect/correct) matches Supabase and Vercel. That makes it the best candidate for wings’ atomic rule format.
Keep llm-security’s “What are you building?” to priority-rules table. Cloudflare’s AI-AND-LLM is deeper (boundary-based), so use it as the base.
Semgrep itself becomes an optional enhancer with a fallback (“if installed, run semgrep --config p/security-audit”), never a requirement. Verify the license for the rule text before copying.
Trail of Bits (reference only, rewrite in our words)
insecure-defaults: fail-open vs fail-secure, where the check is whether the app runs with the default.
sharp-edges: config cliffs and 0, empty or negative values with undefined meaning.
fp-check: a standard vs deep verification split, and rationalizations to reject.
differential-review: risk-first triage and blast radius by caller count.
supply-chain-risk-auditor: “unavailable data is never evidence of risk or of safety”. Its scripts were not sent.
variant-analysis: after a finding, hunt for variants. Cloudflare covers the same ground.
agentic-actions-auditor: niche, only for apps using AI agents in GitHub Actions. Skip.
