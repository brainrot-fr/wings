## B. Constraints this chat established (proposals, nothing decided)

1. **Two peer contracts.** DESIGN.md owns how it looks and EXPERIENCE.md owns how it works, as established in chat 2. This chat adds that the `PG-` file is delta-only over both. ui-ux-pro-max's Master+Overrides is the structural precedent.
2. **Tokens have one home.** Tokens are generated from one source, generated files are read-only, and any other artifact references tokens by name. Copying hex into prompts or docs breaks this.
3. **Frontend forcing questions feed the stack decision record.** The seven are: device/network, LCP target, rendering model, bundle budget, SEO vs auth-walled, design-system home, and WCAG target + owner.
4. **Accessibility floor is WCAG 2.2 AA** (the handoff's decision). Contrast ratios are generated by script, never typed into docs.
5. **Defaults are Baseline-only CSS.** Anything newer is opt-in per browser target in the stack record.
6. **Countable design checks are scripts, and judgment checks are lenses.** This is the same mechanical-before-judgment split as chat 2.
7. **Stubs are marked.** A handler that does nothing does not count as done.

## G. wings-lint additions from this chat

1. Token-reference resolution against DESIGN.md frontmatter (shared with chat 2). It must also flag duplicated hex values outside the token file.
2. Surface closure (chat 2): every `PG-` has a journey and every stated need has a `PG-`.
3. Page-file delta check: a `PG-` file may not restate tokens or component specs.
4. Contrast computed by script for every foreground/background pair, with 1.4.11 checked separately for input and component borders. Use `contrast_checker.py`'s math (chat 8 verified it) and extend it to `rgba`, `hsl`, `oklch` and 8-digit hex.
5. Countable design checks (§D.1), ported from taste-skill's mechanisms (chat 8) rather than its design opinions.
6. Greppable anti-patterns from Vercel's list: `transition: all`, `outline: none` without a replacement, `<div onClick>`, `user-scalable=no`/`maximum-scale=1`, images without dimensions.
7. Client-storage scan: tokens in localStorage/sessionStorage (ties to chat 6's Session rule).
8. State coverage: each data-bound `PG-` declares loading, error, empty and data states.
9. Stub scan: empty handlers and `TODO` without a transparency marker.
10. ID-shape note: ui-ux-pro-max rule names are kebab slugs (e.g. `color-contrast`), which don't fit `[A-Z][A-Z0-9]{0,5}-\d+`. A rule atom needs either an id in that shape or an explicit exemption from the ID linter.
