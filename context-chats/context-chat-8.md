# Context summary: new-repo candidates (mattpocock, taste-skill, modern-web-guidance, open-code-review, ponytail) and the data/script samples

**Architectural reasoning.** This chat supplies the process spine and the mechanical-gate layer that the other chats left abstract. Chats 2 to 7 settled the artifact shapes and rule content. They never settled how an agent moves from intent to tickets to verified code, or how a gate decides pass or fail. The dependency order is:

1. Intent protocol: grilling.
2. Shared vocabulary and decisions: glossary and ADRs.
3. Spec, then vertical-slice tickets that carry seams and blocking edges.
4. Implement and TDD.
5. Review with coverage accounting.
6. Gate verdicts, which must be finite and must never let "not checked" pass.

Rule content (CSVs, a11y) sits last because gates consume it, not the reverse. The headline finding is that the spine skills only work together through one thing: **seams confirmed at spec time and carried in the ticket**. Without that, TDD cannot run unattended.

## B. Constraints this chat established (proposals, nothing decided)

1. **Seams travel in the ticket.** tdd demands user-confirmed seams before any test, but implement-spec runs it in unattended subagents. Only to-spec's seam step reconciles the two, so the seam list must be a ticket field.
2. **Wings owns its tracker and label config.** Every mattpocock spec, ticket and review skill assumes `/setup-matt-pocock-skills`, which wasn't sent and can't ship.
3. **Gates use a finite verdict set.** A check that did not run can never read as PASS. Waivers are narrow: one finding each, at most 5, a reason of 12+ characters, and never on safety checks (taste `gate.mjs`).
4. **A gate must not be able to trap an agent.** `gate.mjs` keeps a block ledger so a stop-hook releases after repeated blocks. This conflicts with the "no gate weakened by the agent that owns the work" rule (§H).
5. **No runtime fetch of unpinned code.** modern-web-guidance runs `npx -y modern-web-guidance@latest` on every task. open-code-review needs a global npm CLI. Both must be vendored or version-pinned, or dropped.
6. **Review reports carry coverage accounting.** `total_files`, `reviewed_files`, `skipped_files` and `coverage_rate` are mandatory, and nothing is discarded silently.
7. **Countable checks are scripts, judgment checks are lenses.** Same split as chats 2 and 7.
8. **Taste-skill's design opinions don't transfer.** It targets marketing sites (one section per screen, 100svh, hero entrances, "never violet"). Take its mechanisms, not its rules.
9. **Asset provenance is a rule.** taste `icons.md` dropped an icon set because the package licence wasn't a grant from each mark's owner. Wings should apply the same test to anything it ships.
10. **Contrast ratios are generated by script, never typed into docs.** The CSV samples already contain errors (§E).

## D. Mechanisms worth carrying

1. **Narrow waivers** with a reason and a cap (`gate.mjs`). Hard FAILs are non-waivable.
2. **Finite verdict plus "not checked ≠ PASS".** This matches the incomplete-checks rule in chat 9.
3. **Block ledger / hook that cannot trap an agent.**
4. **Median-of-3 with a host-busy cap on timing verdicts** (`perf.mjs`).
5. **Coverage accounting on every review** (open-code-review delegate).
6. **Findings need a concrete case** (ponytail). Same candidate-gate idea as Cloudflare in chat 5.
7. **Grep-able debt ledger** from a comment convention (`shortcut:`).
8. **Seams in the ticket.** Vertical slices with blocking edges.
9. **Three-condition ADR test** and a glossary format.
10. **Accent-adjustment notes** in the colour data, so a changed colour records why.

## G. wings-lint and gate additions from this chat

1. Ticket schema check: every ticket carries a seam list, acceptance criteria with required checks, and blocking edges.
2. Gate-verdict check: any gate script emits one verdict from the finite set, and an unrun check cannot produce PASS.
3. Waiver check: exact check plus target plus reason of 12+ characters, at most 5 per run, never on safety checks.
4. Review-report check: `coverage_rate` present, and `skipped_files` non-empty only with reasons.
5. Debt ledger: grep `shortcut:` comments and require a stated limit and an upgrade path.
6. Unpinned-selector scan for `@latest` and bare `npx` (merges with chat 9's pin checker).
7. Import-rule gate per stack pack (dependency-cruiser for TS, chat 3's import-linter for Python).
8. Contrast script extended to `rgba`, `hsl`, `oklch` and 8-digit hex. It must also check 1.4.11 on input and component borders and refuse to emit borderline-only suggestions.
9. CSV and rule data: `Applies To`, `Status`, `Verified At` required, and empty Reasoning cells fail.
