Auth: take the concepts, rewrite the rest

Defects in the wshobson examples:

No rotation: the refresh flow never rotates the refresh token and has no reuse detection. It looks tokens up by hash(token), which only works if hash is deterministic. With bcrypt it fails, and the file never says which.
JWT pinning: jwt.verify doesn’t pin algorithms, issuer or audience.
Session fixation: login sets req.session.userId with no regenerate.
Enumeration: login short-circuits when the user isn’t found, which leaks via timing. Register returns “Email already registered”.
OAuth linking: the Google callback has no state. It also creates a user from the profile email with no email_verified check and no linking policy, which is the account-takeover setup.
Mass assignment: requireOwnership is followed by db.posts.update(req.params.id, req.body), so a client can overwrite userId.
CSRF: it recommends httpOnly cookies, then accepts cookie tokens with no CSRF discussion.
Password policy: 12-character minimum plus composition rules. As far as I know, NIST 800-63B advises against composition rules and for breached-password checks. bcrypt’s 72-byte limit is never handled.
Gaps: its “when to use” lists SSO and multi-tenancy, but the file covers neither. Password reset, email verification, MFA and passkeys are missing too.

Plan: write auth new, as a stack decision record item plus a per-FN authorization line (role, ownership predicate, tenant) that wings-lint checks. Pull the traps from Supabase (the user_metadata trap, TO authenticated without an ownership predicate being BOLA) and alirezarezvani’s backend_security_practices (session regeneration, refresh family). I haven’t fetched the OWASP cheat sheets or NIST 800-63B, and I’d verify against them before writing anything normative.

Conflict table changes
PK type (revised): default bigint generated always as identity. UUIDv7 only for IDs that are exposed or distributed. wshobson and Supabase agree on this. It replaces my earlier “UUIDv7 on PG18+” default. ID type doesn’t fix enumeration anyway, authorization does.
Composite index order: equality columns first, then range or sort. oma and wshobson’s own example agree. Reject “most selective first” wherever it appears.
Error envelope: confirmed as Addy’s {error:{code,message,details}} plus requestId, with no timestamp or path.
Pagination: cursor by default, confirmed.
