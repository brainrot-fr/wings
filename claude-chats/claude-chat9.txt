click-path-audit: the state-store side-effect map (what each action sets and resets) followed by per-handler tracing for sequential undo, async race, dead path and effect interference. It targets bugs agents produce and unit tests miss. It is a review lens, not a script.
skill-comply: spec grammar with required, before_step/after_step; three prompt-strictness levels (supportive, neutral, competing), which matches superpowers’ pressure scenarios; deterministic temporal grading; and _demote_steps_resting_on_failures, so a pass that depends on a failed prerequisite is revoked.
rules-distill: the filter wings uses when merging upstreams. A candidate needs 2+ source skills, an actionable “do X” form, a stated violation risk, and not already be covered, with verdicts Append/Revise/New Section/New File/Already Covered/Too Specific, and it never edits rules without approval.
frontend-design-direction: the content-state matrix (loading, empty, error, partial, success, permission) with each state’s trigger, feedback and next action.
make-interfaces-feel-better: atomic, greppable rules (no transition: all, tabular numerals for updating numbers, concentric radius, hit-area minimum). Matches your countable-checks-as-scripts direction.

4. Cross-cutting

Result-state vocabularies. Seven sources define “this check did not conclusively pass” with different words:

Source	States
ECC verification-loop	VERIFIED / FAILED / NOT PERFORMED / NOT APPLICABLE
ECC browser-qa	SHIP / SHIP WITH FIXES / DO NOT SHIP / INCONCLUSIVE (no baseline ⇒ never a silent pass)
ECC test-collaboration	missing / in progress / unverified / covered / not applicable
Vercel claims	verified / failed / unsupported / unverifiable
Cloudflare findings	confirmed / needs_validation / rejected
taste gate	PASS / FAIL / OPEN / QUICK / OFF / DONE / ERROR / SETUP, plus not-checked
Trail of Bits	“unavailable data is never evidence of risk or safety”

All encode one rule: an incomplete check cannot pass. A design decision remains on whether one shared vocabulary replaces these.

Attested vs measured evidence. gstack’s “no self-certification” rule applies to three ECC mechanisms (design evidence JSON, test-collaboration evidence columns, verification-loop reports). Fields written by the agent are attested; fields produced by a script run (screenshot dimensions, axe JSON, exit codes, test counts) are measured. A gate should mark which is which.

Mechanical before judgment. Seven sources agree: ECC ai-regression-testing, browser-qa, delivery-gate, rules-distill; Vercel verify-before-grade; taste’s hard FAILs; and docs-governance’s audit before semantic review.

Stack-pack provenance. The recurring pattern is a rule with applies_to, status, verified_at and source, plus an explicit “not verified” state. Vercel rules and ECC’s react-performance fail this test (undated version claims).
